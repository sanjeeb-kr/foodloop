3. NoSQL Modeling: Embedding vs Referencing

FoodLoop strategically balances document embedding and referencing based on access patterns and normalization trade-offs.

Embedded Documents

  • pickup_location: Stored directly inside each donation. Avoids joins because location is fixed at listing time and frequently retrieved with the card.
  • claim: Embedded sub-document containing receiver reference and claim timestamp. Enables single-document atomic update operations.
  • status_history: Embedded array of audit transitions (1-to-few bounded growth, strictly within 16MB document limit).

Referenced Documents (ObjectIds)

  • donor_id → users._id: References donor user account. Prevents repeating user profile and organization details in every single donation.
  • claim.receiver_id → users._id: References claiming receiver. Resolved dynamically via $lookup aggregation pipeline stage when needed.
  • Benefit: Updating an organization name or phone number in users requires a single update rather than modifying thousands of historical donation records.
